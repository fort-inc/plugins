# ハーネス診断 — 判定基準

ハーネスを採点するための基準。部門は Claude Code の部品名 7 つと「全体」。部門ごとに観点を持ち、部門と観点の交わり1つが採点項目になる。採点項目は全部で 46 セル。加点は 6 分類で、上限 6。

指摘は全て推奨に留める。重さは AI への影響の大きさであって、直す義務の強さではない。

重さは 大 と 中 の2つ。大は今 AI の判断や安全を壊している。中は AI の性能や整合を下げている。

## 前提(採点しない)

採点するのは、その人にとっての使いやすさではない。今の状態で AI の振る舞いに不満が無ければ、推奨の形でなくてもそのままでよい。この基準が返すのは、本人が自分で直す判断を下すための材料だけ。直すかは本人が決める。作りが揃っているかではなく、管理運営の質だけを見る。

## 判定の決まり

- セルの判定は クリア / 未クリア / 確かめられず。
- 未クリアにできるのは、実物を引用できた時だけ。引用とはファイルと行、または実行結果の写し。
- 見る場所が読めなかった時は「確かめられず」。
- 同じ1つの事実で2つ以上のセルに当たる時は、両方に当てる。セルは観点が違うので二重ではない。ただし同じセルの中で事実が幾つあっても、そのセルは1回だけ未クリア。
- 跡を探す場所は 3 つ。CLAUDE.md から指された記録の直近 5 件、`git log` の直近 5 件、hook や skill の本文が名指しする記録先。そこに無ければ跡は無いとする。跡が無い事を根拠にする時は、探した場所を並べて書く。
- 最終更新は、git に入っているファイルは `git log -5 -- <パス>` の先頭の日付、入っていないファイルは `ls -la` の日時。中身に書かれた日付は使わない。

## 起動のたびに読まれる物の範囲

次を「起動のたびに読まれる物」として扱い、全部読む。user 階層と起動ディレクトリを分けて集め、診断書でも分けて書く。

- 両階層の CLAUDE.md と `CLAUDE.local.md`
- `paths` の付いていない rules
- CLAUDE.md が `@` で取り込んでいる先
- CLAUDE.md から名指しされた文書
- 毎回読まれる記憶。`MEMORY.md` の先頭 200 行、または CLAUDE.md から「毎回読む」と指されたファイルを指す

起動ディレクトリより下の階層の物は、この範囲に入れない。下の `CLAUDE.md` はそのフォルダのファイルを扱う時に読まれ、下の `.claude/skills/` も同じ時に見つかるためで、起動のたびに届く物ではない。数は「見たもの」に添え、読まなかった分も「見たもの」の行に書く。

この範囲の行数を合計し、診断書の「見たもの」に添える。二重と矛盾は、階層と文書をまたいで見る。これが正しいと名乗る文書が実物より古い場合は 1-3 と 1-11 に当てる。CLAUDE.md から指されていない文書は、この範囲に入れず、根拠 1-12 で見る。

skill と subagent は frontmatter と行数だけ読む。例外は3つ。外から持ち込んだ skill と plugin の本文は読む。subagent の本文も読む。description が重なる skill の対と、常時読まれる決まりと同じ事柄を扱う skill は、本文も読んで見比べる。記憶は索引と直近だけ読む。読まなかった物は診断書の「見たもの」の行に1文で書く。

## 公式の線

部門ごとに1本。公式文書に根拠のある線で、外れている事実はセルを未クリアにする根拠になる。

| skills / commands | `.claude/skills/<名前>/SKILL.md` の形。frontmatter を書くなら先頭行を `---` にする。description に何をするかといつ使うかを書く。description は公式の推奨で、無くても読み込まれるが呼ばれにくい | https://code.claude.com/docs/en/skills |

| hooks | 自前の hook は settings の `hooks` の下に登録する。plugin と、skill や subagent の frontmatter にも置ける。実体は絶対パスか `${CLAUDE_PROJECT_DIR}` で指す。command 型は exit 2 と stderr、または decision の JSON で止める。PermissionRequest は exit 2 が効かず decision の JSON で返す。HTTP 型も JSON で返す | https://code.claude.com/docs/en/hooks |

この表に無い外れ方は根拠にしない。

## 部門と観点

観点は 17 個。1 公式の機構に乗っているか / 2 常時届く量 / 3 責務と置き場 / 4 二重と矛盾 / 5 実物とのずれ / 6 正と名乗る物の更新 / 7 戻せない操作が止まるか / 8 止める物を最小に / 9 効いているかを確かめているか / 10 増やす一方になっていないか / 11 呼び分けができるか / 12 記憶が自前で回っているか / 13 接続の効く範囲 / 14 鍵の扱い / 15 git 管理 / 16 訂正の行き先と回転 / 17 置く階層。

落とす根拠の列に出る `1-1` のような番号は、次の節の根拠の番号。未クリアにできるのは、番号の付いた根拠に当たる時だけ。番号の無い文は、何を引くかの指示。

## 点の付け方

| 決め事 | 内容 |

| 部門の満点 | 「部門と観点」の各部門に書いた満点。合計 100。確かめられなかったセルがある部門は、縮めた満点に置き換える |
| 部門の点 | 満点 × (○ の数 − 大の数 + 中の数 ÷ 2) ÷ 全項目の数。下限 0 |
| ○・大・中・全項目 | ○ はクリアのセルの数。大と中は、未クリアのセルをその根拠の一番重い物で分けた数。同じセルに事実が幾つあっても数えるのは 1 回。全項目はその部門のセルの数。中は半分の値段で数える。大は自分の持ち分を失い、さらに ○ を 1 つ消す。中が無ければ、大が ○ と同じ数になった時に 0 になる |
| 小数の扱い | 部門の点は小数のまま持ち、全体の計算に使う。診断書に出す時だけ四捨五入する |
| 確かめられなかったセル | そのセルがある部門は、全項目の数からそのセルを除き、満点を「確かめたセルの数 ÷ セルの数」の割合で縮める。縮めた満点を、式にも、全体の点の分母にも、診断書に出す満点にも使う。過半を確かめられなければ部門ごと外す |

| MCP を使っていないとする条件 | 定義がどこにも無く、セッションの冒頭の一覧にも接続が無い時だけ |
| 全体の点 | 見た部門の点の合計 ÷ 見た部門の満点の合計 × 100 に加点を足し、最後に四捨五入する。100 を超えたらそのまま |
| 見た部門が無い時 | 使っていない部門と確かめられなかった部門だけで、見た部門が 1 つも無い時は、全体の点を出さず「確かめられなかった」と書く。加点は足さない |

## 加点

有れば足すのではなく、回っていれば足す。採点が終わった後に、集めた物のうち 46 セルのどの判定にも使わなかった仕掛けを並べ、1 つずつ下の加点の分類に当てる。加点の分類は物差しであって、探す表ではない。記憶と安全は減点側の部門が採点済みなので、加点の分類に置かない。

| 決め事 | 内容 |
|---|---|
| 加点の候補 | 集めた物のうち、46 セルのどの判定にも使わなかった仕掛けで、下の 6 分類のどれかに当たる物。script、道具、自動で走る処理、工程の型、見せ方の型 |
| 数える条件 | 目的が名前か説明か記録から分かる。直近 30 日に回った跡を引用できる |
| 点 | 分類ごとに、条件を満たす工夫が 1 つでもあれば 1 点 |
| 加点 | 回っている分類の数。上限 6 |
| 0 の時 | 加点が 0 でも診断書に「加点 0 / 6」と出す |

| # | 加点の分類 | 何のための工夫か | 例 |
|---|---|---|---|
| 1 | 認知負荷対策 | 人が読む物と判断する物の量と形を軽くする | 出力の形の決まり。確認物を人が読める形にして開く道具 |
| 2 | 工程の型 | 作業を決まった型で進め、人の判断を挟む場所が決まっている | 実装の前に仕様を書き切る型。承認が記録として残る |
| 3 | 自己検証 | 効いているかを AI 自身が確かめ、合否が機械で返る | AI が自分で走らせて合否が返る手段。別の文脈の検品役を立てる |
| 4 | 委任と使い分け | 渡し先とモデルを仕事ごとに分け、渡す物を型にする | 渡す時の指示書の型。モデルの使い分け |
| 5 | 見える化 | 今どこか、何が起きたかを人と AI が同じ物で見る | 現在地を 1 枚に出せる道具。人が見る画面 |
| 6 | 改善の回転 | 指摘と失敗が決まった先へ入り、次の回に効く | 繰り返す訂正の行き先。定期の見回り |

例は当たる物を示すためで、網羅ではない。認知負荷対策は人の側の工夫で、AI の認知負荷という考えは採らない。

## 内側の分類

内側の分類。診断書に名前も番号も出さない。推奨の並び順と、診断書の締めの材料にする。根拠ごとの結びは、各部門の表の「結び」の列にある。

| # | 現れ方 |
|---|---|
| 1 | 前提をすっぽかす。頼んだ事の前提や制約を無視して進める |
| 2 | 同じ指摘を何度もする。直したはずの振る舞いが戻る |
| 3 | 書いてあるのに守らない |
| 4 | 勝手に危ない事をする。消す・送る・公開する |
| 5 | 古い前提で動く。終わった事を未着手と思う、消えた物を探す |
| 6 | 遅い・高い・読む量が溢れる。無駄な物を読んで肝心の仕事に届かない |

使い方。推奨は重い順に並べ、同じ重さの中では、当たった結びの数が多い物を先に置く。診断書の締めは、当たった結びの現れ方を2〜3個、その環境の言葉に置き換えて書く。番号も分類名も出さない。

## 仕組みの裏付け

Claude Code の仕組みとして言い切ってよいのは次だけ。他は言い切らない。

- CLAUDE.md は起動時に読まれ、文脈として届く。強制ではない。 https://code.claude.com/docs/en/memory
- 起動ディレクトリより上の階層の CLAUDE.md は起動時に、下の階層はそのフォルダのファイルを読んだ時に届く。 https://code.claude.com/docs/en/memory
- 起動ディレクトリより下の `.claude/skills/` も起動時には読まれない。そのフォルダのファイルを最初に読むか書いた時に読まれ、その後は使える。それまでは名前で呼べない。上の階層の skill は git の根まで起動時に読まれる。 https://code.claude.com/docs/en/skills https://code.claude.com/docs/en/memory
- `@` の取り込みは起動時に全部展開されて届くので、分けても読まれる量は減らない。取り込みは4段まで。 https://code.claude.com/docs/en/memory
- CLAUDE.md は 200 行以内が目安。4 MiB を超えると読まれない。 https://code.claude.com/docs/en/memory
- 決まりが矛盾すると、どちらが選ばれるかは決まらない。 https://code.claude.com/docs/en/memory
- Claude Code が読むのは CLAUDE.md で、AGENTS.md ではない。両方あるなら取り込みか symlink で1つにする。 https://code.claude.com/docs/en/memory
- `paths` の無い rules は起動時に `.claude/CLAUDE.md` と同じ重さで読まれる。`paths` を付けると、合うファイルを読んだ時だけ届く。 https://code.claude.com/docs/en/memory
- user 階層の rules は起動ディレクトリ側の rules より先に読まれ、起動ディレクトリ側が優先される。 https://code.claude.com/docs/en/memory
- 人向けのメモを HTML コメントで書くと、文脈には載らない。 https://code.claude.com/docs/en/memory
- skill の本文は呼ばれた時だけ読まれる。毎回届くのは description。 https://code.claude.com/docs/en/skills
- skill は `<名前>/SKILL.md` の形だけが読まれる。ファイルを直に置いた物は読まれない。frontmatter は先頭行が `---` の時だけ読まれる。name と description は無くても読み込まれる。name はフォルダ名が既定、description は推奨で、無いと本文の最初の行が説明になる。 https://code.claude.com/docs/en/skills https://code.claude.com/docs/en/debug-your-config
- skill は 500 行未満が目安。一度読み込まれた本文はその後のやり取りに残り続ける。 https://code.claude.com/docs/en/skills
- description と、いつ使うかの文は合わせて 1,536 文字で切られる。先頭に肝心の用途を置く。 https://code.claude.com/docs/en/skills
- description が曖昧だったり重なっていたりすると、違う skill が読まれるか、要る物が読まれない。 https://code.claude.com/docs/en/features-overview
- skill の `allowed-tools` は、一度も信頼していないフォルダでも効く。持ち込んだ skill は先に読む。 https://code.claude.com/docs/en/skills
- `.claude/commands/<名前>.md` は skill と同じ物として扱われる。 https://code.claude.com/docs/en/slash-commands
- subagent は `.claude/agents/<名前>.md`。name と description が要る。tools を省くと、使える道具を全部引き継ぐ。 https://code.claude.com/docs/en/sub-agents
- 組み込みの Explore と Plan の subagent には CLAUDE.md が届かない。 https://code.claude.com/docs/en/debug-your-config
- 自前の hooks は settings の `hooks` の下に書く。単独の設定ファイルは無い。plugin の `hooks/hooks.json` と、skill や subagent の frontmatter にも置ける。 https://code.claude.com/docs/en/hooks https://code.claude.com/docs/en/debug-your-config
- command 型の hook は exit 2 で止め、理由は stderr に書く。PermissionRequest は exit 2 では止まらず、decision の JSON を返して止める。HTTP 型の hook も JSON で返す。止められない事象もある。 https://code.claude.com/docs/en/hooks https://code.claude.com/docs/en/hooks-guide
- PreToolUse の hook は標準出力の JSON でも止められる。`hookSpecificOutput.permissionDecision` で止め、止めた理由は `permissionDecisionReason` に書く。 https://code.claude.com/docs/en/hooks
- hook の実体は絶対パスか `${CLAUDE_PROJECT_DIR}` で指す。`${CLAUDE_PROJECT_DIR}` は hook が走る時の作業ディレクトリに関わらず、起動したプロジェクトの根を指す。相対パスは作業ディレクトリが変わると同じ実体を指さない。 https://code.claude.com/docs/en/hooks https://code.claude.com/docs/en/hooks-guide
- hook の matcher は1本の文字列で、`|` 区切り、大文字小文字を区別する。配列を書くと settings 全体が読まれなくなる。 https://code.claude.com/docs/en/debug-your-config
- hook は shell を走らせる。共有や本番の環境へ入れる前に中身を読む。公式の書き方の作法は、渡された値を検証する、shell の変数を引用符で囲む、`..` を含むパスを弾く、実体を絶対パスで指す、`.env` や `.git/` や鍵のファイルを読み飛ばす、の5つ。 https://code.claude.com/docs/en/hooks https://code.claude.com/docs/en/hooks-guide
- settings は厳格な JSON。コメントや末尾のカンマは読み込みを壊す。 https://code.claude.com/docs/en/settings
- settings の優先順は 管理者 → コマンドライン → `.claude/settings.local.json` → `.claude/settings.json` → `~/.claude/settings.json`。同じ一覧のキーは足し合わされる。 https://code.claude.com/docs/en/settings
- `~/.claude.json` は状態の置き場。permissions・hooks・env は `~/.claude/settings.json` に書く。 https://code.claude.com/docs/en/debug-your-config
- 許可の判定は deny → ask → allow の順。広い deny は狭い allow の例外を持てない。 https://code.claude.com/docs/en/permissions
- 読むだけの道具は、作業ディレクトリの中なら設定が無くても確認が出ない。読むだけの道具とは、ファイルの読み取りと Grep を指す。shell も `ls`・`cat`・`echo`・`pwd`・`head`・`tail`・`grep`・`find`・`wc`・`which`・`diff`・`stat`・`du`・`cd` と読み取りだけの `git` は組み込みで確認なしに通る。この一覧は設定で変えられない。 https://code.claude.com/docs/en/permissions
- 秘匿ファイルは `Read` の deny で塞ぐ。`Read` の deny は Edit と Write も塞ぐが NotebookEdit は塞がないので、`Edit` の deny も併せる。 https://code.claude.com/docs/en/permissions
- コマンド名での deny は安全の境界にならない。別の書き方、別のパス指定、`sh -c` の中は素通る。 https://code.claude.com/docs/en/permissions
- `bypassPermissions` は `.git` と `.claude` への書き込みも素通しにする。 https://code.claude.com/docs/en/permissions
- user 階層の settings に `/` で始まるパスの deny を書くと、`~/.claude/` 基準で当たる。全てのプロジェクトへ効かせるには `//` の絶対パスか `~/` の形で書く。Windows のパスは POSIX の形に直してから照合される。 https://code.claude.com/docs/en/permissions
- MCP の定義はリポジトリ直下の `.mcp.json` か `~/.claude.json`。キーは `mcpServers`。`settings.json` に書いても読まれない。 https://code.claude.com/docs/en/mcp https://code.claude.com/docs/en/debug-your-config
- `claude mcp list` は接続の状態を出す。この skill はそれを走らせず、セッションの冒頭に出ている MCP の一覧で同じ事を見る。 https://code.claude.com/docs/en/mcp
- 外部の内容を取ってくる接続は、信頼できるか確かめてから繋ぐ。 https://code.claude.com/docs/en/mcp
- MCP の `command` か `args` が相対パスを使っていると、起動するディレクトリによって接続が立ち上がらない。手元の script は絶対パスで指す。`npx` や `uvx` のような PATH 上の実行名はそのままでよい。 https://code.claude.com/docs/en/debug-your-config
- auto memory は `~/.claude/projects/<プロジェクト>/memory/` に置かれる。`MEMORY.md` の先頭 200 行か 25KB までが毎回読まれ、超えた分は届かない。 https://code.claude.com/docs/en/memory
- auto memory はそのマシンだけの物で、別のマシンには渡らない。主の会話の auto memory は subagent には載らない。fork は例外で、subagent は `memory` の欄で自前の記憶を持てる。 https://code.claude.com/docs/en/memory
- auto memory の話題別ファイルは起動時には読まれない。必要になった時に読まれる。 https://code.claude.com/docs/en/memory
- 何が届いているかは `/context` の Memory files、`/status`、`/permissions`、`/hooks`、`/mcp`、`claude doctor` で確かめられる。 https://code.claude.com/docs/en/debug-your-config
